## 它做什么

webot 登录在一个商务微信号上，只做这几件事：

- **Claude 中转**：允许的人在私聊里发「cc 任务」，机器人把任务放进队列，Mac 上的 worker（`tools/claude_relay/worker.py`）取走交给 Claude Code，做完把结果发回私聊。
- **达人副驾驶**（`PRM_COPILOT`）：已登记达人的私聊不回任何话，静默交给 Mac 起草，草稿在控制台「待审批」里等运营发送、修改或丢弃；合作单、寄样、物流、清理收件信息都在控制台里。
- **微信边缘**（`PRM_EDGE`）：这台电脑只替 Mac 上的业务服务收发名单里达人的微信（协议见 `edge-protocol.md`）。
- **加百应达人微信**（`PRM_FRIEND_ADD`，默认关）：百应邀约来的达人留了微信号 / 手机号（百应私信里我们邀约的会话里她发的联系方式卡片、打的字，开着 `PRM_BUYIN_SYNC_MIN` 时自动出现；或者运营在「合作单」页手动填），运营在控制台确认一次，机器人用好友管理发一次好友申请；她通过以后运营点「是她，登记并关联」，登记成达人并记下她的抖音号。
- **管理员命令**：管理员（`ADMIN_WXID`）在私聊里发 `查状态`、`添加好友 号码 [附言]`、`同意好友`、`自动同意好友 开|关`、`待加达人`、`加达人 编号`、`不加达人 编号`、`帮助`。

**它从不陪聊**：没有聊天模型、不需要任何 AI 密钥。所有群消息（@ 它、叫它的名字也一样）和其他人的私聊只记录、不回复。

## 控制台

打开 EXE 后会弹出网页控制台（只监听本机），左侧六页：

- **运行状态**：机器人在不在线、处理了多少消息、Mac worker 在不在
- **中转代理**：中转任务列表（可取消）、Mac 端怎么接、中转设置（token、端口、谁能用）
- **待审批**：达人的回复草稿，点「发送」才会发出去
- **合作单**：登记 / 停用达人，合作阶段、寄样、物流
- **微信连接**：微信后端、读哪些私聊和群、数据目录、OCR 备选
- **运行日志**

电脑微信不在线的那几段（哪段时间、要在手机上看一遍）在每页顶上提醒，点「看过了」才消失。

首次打开是三步设置：微信密钥 → 微信设置 → 中转设置。

## 安装

### Windows

```bash
pip install -r requirements.txt
cd ui && npm install && npm run build && cd ..
python desktop.py
```

打包成 EXE：`pyinstaller build.spec`，输出 `dist/webot.exe`。

前提：电脑上已登录微信。机器人要读的群需要先添加到通讯录（群聊右上角 `···` → 开启「添加到通讯录」）；微信后端至少要读到一个群才会启动，填一个测试群就够。

### macOS（实验）

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements-macos.txt
cd ui && npm install && npm run build && cd ..
python desktop_mac.py
```

需要在系统设置中给终端授权「辅助功能」权限。`desktop_mac.py` 默认写入
`WECHAT_BACKEND=mac_hybrid`，通过 WeFlow 直接读取本地 WCDB，并使用辅助功能发送消息；
不需要额外启动消息读取服务。

首次配置 WeFlow 的本地读取能力时，在项目根目录运行：

```bash
python tools/macos/weflow_setup.py extract-keys
python tools/macos/weflow_setup.py import-keys
python tools/macos/weflow_setup.py diagnose
```

密钥会保存在微信账户目录的 `all_keys.json`。若普通提取没有结果，可在重启微信后使用：

```bash
python tools/macos/weflow_setup.py extract-keys-restart-hook
```

`WECHAT_BACKEND=mac_ui` 是只依赖辅助功能的实验性回退模式；需要数据库直读时使用
`WECHAT_BACKEND=mac_hybrid`。

### Mac 上的 worker

Claude 中转和达人副驾驶的起草都由 Mac 上的 worker 完成，安装和配置见 `tools/claude_relay/README.md`。

## 常见问题

**需要 AI 密钥吗？**
不需要。机器人自己不调用任何模型；Claude Code 跑在 Mac 上。

**群里 @ 它会怎样？**
不会有任何回复，消息只记录。

**微信能最小化吗？**
读消息不受影响，发消息时微信窗口需要可见。

**电脑微信退出了（重启电脑、升级微信、被挤下线），这段时间达人的消息怎么办？**
电脑微信重新登录后，默认不会把退出期间发到手机上的消息同步过来，机器人也就读不到。扫码登录时，在手机的确认页上勾选「同步最近的聊天记录」，这段时间的消息就会同步到电脑，机器人会自动补交成草稿（2026-10-28 真机确认）。所以电脑微信要一直登录着；不得不退出时，重新登录一定要勾选同步。

机器人会记下电脑微信哪段时间不在线（运行中看到它掉线，或者启动时发现它和机器人一起停过），控制台每页顶上一直提醒到你点「看过了」：请按提醒在手机微信上把那段时间达人的私聊看一遍。电脑微信重新登录、同步进来以后，机器人不用重启就会把这段时间的消息补交成草稿（一律先审）。用微信边缘（`PRM_EDGE`）时，Mac 的控制台也有同样的提醒。被挤下线时机器人能不能认出来，还在等真机确认。

**机器人停了一会儿，消息会丢吗？**
只要电脑微信一直登录着就不会。机器人重启后，会把停机期间已登记达人发来的消息补交成草稿（`PRM_CATCHUP_HOURS`，默认 12 小时以内）：晚于 5 分钟读到的草稿一律要人审，并注明「机器人没在读微信时收到」；更早的只记录，合作单上提醒运营去看。

**寄样单的运单号和签收还要手动填吗？**
签收不用填，运单号目前还要填（`PRM_SAMPLE_SYNC_MIN`，默认每 60 分钟查一次）。机器人建好的聚水潭寄样单，会定时交给 Mac 上的 worker 到聚水潭查一次状态（只读，不改聚水潭里的任何东西，也不读收件信息）：
- 聚水潭显示已签收：合作单自动标「已签收」，开专属佣金的草稿照常一款一款出来（人工接管、暂停或达人停用时先欠着，恢复后自动补上）；
- 聚水潭显示已发货：它的寄样单列表里没有运单号（2026-10-29 核对过，已签收的单也没有），合作单会提醒「已发货，但没给运单号」，请照旧在合作单上填运单号，「待审批」里就出现发货通知；以后聚水潭给出运单号了，机器人会自动填上（发货通知照旧要你点「发送」）；
- 寄样单被驳回或删除、你手填的运单号和聚水潭的对不上（机器人不会改你填的）、建单 3 天还没发货、发货 10 天还没签收：合作单上标红写明，请到聚水潭寄样管理或物流那边看一下；
- 合作单上写「聚水潭登录失效」：到 Mac 的调试 Chrome 里重新登录聚水潭，下一次查成功后这条提醒自己消失。

手动填运单号、手动标「已签收」照样能用。被删除的寄样单的提醒，重新建好寄样单、或者在合作单上改一次阶段，就会去掉。

**开专属佣金时某一款一直开不成？**
在「待审批」里对这一款的草稿点「不发」，机器人这一轮就跳过它，接着派下一款；合作单上会显示「开好 k/n」。
以后要补开没开好的款：把合作单的物流改回「运输中」，再标「已签收」，机器人只问还没开好的那几款。

**达人要「专属链接 + 前缀」怎么办？**
起草的 Claude 听到她（或老板在三方群里）说要「专属链接」、说了「前缀」，或者明说要一条只给她的链接（只说「发个链接」「链接发我」「有链接吗」的是普通的商品链接，不算），会在合作单的信息里记一条「专属链接前缀」（比如「【小美专属】」）。之后开专属佣金的那一路每一款开好，机器人接着派一步建这一款的专属链接（抖店渠道品，照店里的做法：专属达人带货、标题前缀「【某某专属】」、渠道价按日常价 9 折取整到元、每个颜色 100 件、长期有效），再到下一款的专属佣金；一款的专属佣金没开好就不建它的链接。「待审批」里那份草稿每个颜色一行：日常价 → 渠道价、放多少件、主商品还能分多少，前缀写着几个字符；她已经绑在这个商品的渠道品上（店里手工建的也算）就不再建，卡片上列出那个渠道品和它的链接，复制给她就行。开佣金那一路派的链接，要绑的 UID 不是这一轮寄样单上的就批不了；别的链接草稿，UID 不在她任何一张寄样单上只标「要注意」（她可能有两个抖音号），看过没问题照样能批。批准以后建好、绑上她、核验通过，才把带链接的回复发给她。专属佣金都开完以后她才要链接的，记下那一刻机器人就开始一款一款建；还不能建的（手头那一步没办完、还不知道前缀）合作单上写着哪一款在等、等什么。
她要的前缀超过 12 个字符（汉字算 2 个，比如「【小美美呀专属】」是 14 个），机器人不照写，让 Mac 留名字的前几个字加「专属」改短（「【小美美专属】」）或者问她；之前卡在前缀太长、被点了「不发」的那一款，她给了能用的前缀以后会再派一次。
建好了渠道品却没绑上她（比如建的时候日常价变了、绑定被拒）：那份草稿标红，写着渠道品 ID、链接和两条路——在抖店「渠道商品管理」把她绑上、自己把链接发给她；或者把它下架、删掉。处理好了点「我已处理」。这个渠道品还在、又没绑上她时，Mac 不会给她再建同一款的链接。

**这次更新（专属链接、起草的上下文、直播手卡、微信里审批草稿、接群），Windows 和 Mac 先更新哪边？**
照这个顺序（2026-11-10 统一，`CLAUDE.md`、`tools/claude_relay/README.md`、`.env.example` 写的都是它）：
1. Windows：拉代码、`cd ui && npm run build`、重启机器人；新开关（`PRM_DRAFT_CONTEXT`、`PRM_HANDCARDS`、`PRM_WECHAT_REVIEW`、`PRM_LINKED_GROUPS_AUTO`）先都关着。
2. Mac：更新代码，跑一次 `python3 tools/claude_relay/worker.py --check`，两个 worker 都 `kill -USR1` 重启。
3. Windows：在 `.env` 里打开要用的开关，再重启机器人。
4. 「待审批」里已经在等的寄样单和专属链接草稿，各点一次「重新预览」再批准。

为什么先 Windows：新 Mac 遇到旧机器人时，不会把专属链接放进草稿（旧机器人会把回复里的 {链接} 原样发出去）：草稿里去掉这个动作，回复里有 {链接} 就连回复一起去掉，「待审批」里写着「Windows 上的机器人比这台 Mac 旧…」。看到这句就去更新 Windows；那一份请人工回她，之后的草稿照常。
Mac 和 Windows 之间网络一时不通、Mac 问不到机器人时也一样不给（连着问三次，问不到就用一小时内上一次问到的结果）：开佣金那一路的建链接那一步，新机器人过 5 分钟自己再派一次（最多三次，还不行就在合作单上说「请运营处理」）；她要链接的那条消息，等她下一条消息时一起起草，合作单上写着「草稿没写成」。

**邀约卡已经给过 25% 专属佣金的达人，签收以后会再开一次吗？**
不会。用批量邀约工具发的卡（带专属佣金）平台已经建了策略：开专属佣金时 Mac 先查邀约工具的台账，这一款邀约卡开过就不碰平台、当作开好，接着开下一款；合作单上写「开好 k/n 个（其中邀约卡开过 …）」。台账里查不到的（比如在百应页面上手动发的卡）认不出，批准前看一眼预览里的「平台提醒」，已经有策略就点「不发」。

**平台动作的结果「不确定」，同一款再批被拒了？**
结果不确定（平台可能已经建了）时，同一款商品不能再批，免得重复建。先到平台后台核对：
确实没有，就在那份标红的草稿上点「我已处理」，再批准新的；已经有了，就对新草稿点「不发」，再点「我已处理」。

**批寄样单时说「这位达人 7 天内已经建过寄样单 #…」（或者「还有一份寄样单 #… 在等」「有寄样单 #… 的结果不确定」）？**
同一张合作单 7 天内已经有一张核验成功的寄样单、有一张正在建，或者另一边（她的私聊和接手的群各一份）还有一份在等时，第一次批准不执行，免得一位达人建两张单。那一份在「待审批」最上面标红、带「我已处理」：确实要再寄一次（补寄、多寄），点它的「我已处理」，再回来批准这一份；不用再寄，点这一份的「不发」，再点那一份的「我已处理」。7 天内有一张寄样单结果不确定（聚水潭里可能已经建了）时也一样：先到聚水潭寄样管理核对那一张建了没有，确实没有（或者要补寄）就点它的「我已处理」再批准这一份，已经有了就点这一份的「不发」，再点那一份的「我已处理」。

**接手的群（「接群」）里的草稿为什么不自动发？**
群里的人都看得到我们发的话，所以默认（`PRM_LINKED_GROUPS_AUTO` 关着）接手的群里的草稿一律等你看过再发：自动发送门槛、下班时段、自动模式、开场白自动发、签收后问一句都不自动发，卡片上写着原因。想和老板拉的群一样自动发，设置里打开「手动接的群也自动发」（`.env` 的 `PRM_LINKED_GROUPS_AUTO=on`）、重启机器人；接群那一刻她在等我们回的那几句的草稿照旧等你看。

**达人那边自己拉的群，机器人怎么才会读？（`PRM_GROUPS_AUTO_LINK`、`PRM_GROUP_HER_SIDE`，2026-11-11，默认都关）**
以前只有老板新拉的群会自动接手，别的群要管理员在微信里发「接群」。设置里打开「认得出是谁的群自动接手」（`.env` 的 `PRM_GROUPS_AUTO_LINK=on`）、重启机器人以后，机器人每分钟看一遍这个号所在的群（人数不超过「老板拉的群最多几个人」，老群也看）：
- 群里恰好只有一位登记过、在用的达人，她也还没有别的接手的群：自动把群接到她的合作单上，和你发「接群」一样（不写开场白，群里最近的话当背景，她那边在等回复就起草一份，这一份一律等你看）。管理员微信里收到一条「已自动接群：…」，不对就回「不接群 群名」。
- 群里有两位以上登记过的达人：不猜。「合作单」页顶上的卡片问你是谁的群，管理员微信里也说一声，回「接群 群名」选。
- 一位登记过的达人都没有：不动。打开开关时已经在的群不打扰；之后才出现、或者才有人说话的群，管理员微信里提醒一次「…还没接：回「接群 群名」」，同一个群只说一次。
- 你说过「不接群」「不接了」「群已经不在了」「不接」「这个群不是达人」的群，机器人不会再自己接；合作单自己的三方群（「拉三方群」建的）照旧只读。
自动接的群发不发还是看「手动接的群也自动发」：关着就都等你看。

群里常常是她的助理、商务在说话（「帽子到了，上一下链接」），不是登记的那个号。打开「群里她那边的人说话也起草」（`PRM_GROUP_HER_SIDE=on`）以后，接手的群里除了我们自己、老板、管理员、能用 cc 的人和别的登记过的达人，其余人说的话都和她本人的话一样起草（门槛、下班时段、自动模式都一样）。交给 Mac 时这些话前面标着「〔她那边的人〕」，不带这个人的名字，回复照旧称呼「老师」「您」。注意：群里如果有我们自己的同事（不是这个号、不是老板、不是管理员），他们说的话也会被当成她那边的；这样的群先不要开，或者让同事不在群里说话。上线顺序：先更新 Windows（两个开关关着）、再更新 Mac 的 worker 并在 kb 里加上「群里她那边别的人说话」那一段、最后在 Windows 上打开开关重启。

**草稿标红，说「和另一个聊天同名」？**
微信里有两个聊天叫同一个名字（比如达人的昵称和某个群名一样），机器人没法确定发给谁，就不发。请手动在微信里发这条，或者在微信里给这位达人设一个不重复的备注，重启机器人后就能照常发。
