## 一、一页看懂（2026-10-25）

**已经能用（在模拟模式下）**

- 名单里的达人在私聊里要样品时，机器人会：没说要哪款就先问 → 查库存 → 逐项追问收件人、电话、地址，并请对方发小红书主页 → 信息齐了生成审批单。审批前的回复不承诺寄出时间和快递。〔10-25 · 测试 `tests/test_influencer_acceptance.py`、`test_influencer_dialogue.py`〕
- 名单以外的私聊不受影响，照常由原来的聊天机器人回复。〔10-25 · 测试 `test_influencer_acceptance.py`〕
- 运营在控制台的「达人审批」页核对后通过或驳回。通过后在聚水潭建出库单、在小红书绑定佣金；同一张单只能执行一次，重启以后也一样。〔10-25 · 测试 `test_influencer_approval.py`，浏览器测试 `test_influencer_console.py`〕
- 审批单、达人名单、没补齐的申请都存在本机数据库里，重启不丢。〔10-25 · 测试 `test_influencer_store.py`〕
- 全部自动化测试 3441 个通过、1 个跳过、0 个失败，其中达人模块 102 个。〔10-25 · 测试〕
- 名单里的达人发来的不是索样（比如问上新、问发货），不交给聊天机器人：机器人只回一句"收到，核对后再回复"（同一人 6 小时内最多一次），消息进控制台「待处理」，由运营人工回复。名单以外的私聊照常由聊天机器人回复（公司号，D13）。〔10-25 · 测试 `test_influencer_dialogue.py`〕

**还不能用**

- 聚水潭：真实接口还没接，现在只能用模拟模式，库存和单号都是假的。〔10-25 · 代码〕
- 小红书 CLI：同事还在开发，还没交付。〔10-24 · 告知〕
- 真实微信：这台 Mac 上的机器人还没正式收过消息，数据库里还没有消息表。〔10-25 · 本机〕

**现在要注意的**

- 批准或驳回后，机器人不会自动通知达人，要运营把审批卡上的消息复制到微信里发。这是有意这样做的。〔10-24 · 拍板 D9〕
- 提醒只做在控制台里，不推送到微信或飞书（D14）：左栏「达人审批」上显示待审批和待处理的数量，缺货会进「待处理」，执行失败记在审批单上。运营要记得打开控制台看。〔10-25 · 测试〕

想自己试一遍，步骤见 `handoff.md` 第 8 节"怎么用达人审批页"。

## 二、为什么不让 Claude Code 直接当服务器（原稿第一节）

**结论不变，代码也是这么做的**：Claude Code 用来写代码；跑业务的是一个常驻在 Mac 上的 Python 服务，基础是开源的微信机器人 webot，达人模块挂在它的私聊入口上。〔10-24 · 代码〕

原稿的理由和技术细节，有两处要更正：

- "Claude Code 调外部命令必须有人手动确认，非交互下直接报错"：这是同事实际碰到的情况，我们没有复现。〔告知，未验证〕不过，不管能不能配成免确认，业务都应该放在专门的常驻服务里：要 7×24 运行，每一步都要能测试，出了错要能追查。
- "常驻服务（如 fastapi + anthropic SDK）直接调用 Claude API"：实际用的是 webot 自带的服务，基于 Python 标准库的 HTTP 服务，不是 fastapi。全局配置的大模型是 DeepSeek（`AI_BACKEND=deepseek`），不是 Claude。达人模块本身不调用任何大模型，全靠规则识别。〔10-25 · 本机 `.env.macos`、代码〕

**向上汇报的话术（更正版）**

原稿的话术里有三处和事实不符：

| 原稿说法 | 事实 | 核实 |
|---|---|---|
| "使用的是 Claude 最顶尖的底层推理大脑" | 全局用的是 DeepSeek；达人模块不调大模型 | 10-25 · 本机、代码 |
| "根据生产级工程标准做了服务端容器化" | 没有容器，直接在 Mac 上从源码运行；仓库里没有任何容器配置 | 10-25 · 代码 |
| "确保了 7x24 小时无人值守的稳定性" | 还没有长时间运行过 | 未验证 |

建议改成：

> "跑在 Mac 上的是一个常驻的 Python 服务，基础是开源的微信机器人 webot，达人模块是我们在上面加的，代码由 Claude Code 协助编写和审查。建单、绑佣金这些花钱的动作，都要运营在控制台审批后才执行，每张审批单只能执行一次；达人模块的自动回复不做任何承诺。达人发来的其他消息转运营人工回复，机器人不替我们答应任何事。目前有 3441 个自动化测试，在模拟模式下全部通过；聚水潭、小红书 CLI 和真实微信还没有联调。"

## 三、系统现在是怎么搭的（替换原稿第四节的代码蓝图）

原稿第四节的代码是设想中的骨架，和实际代码对不上：没有 Win 端网关，批准后也不会自动给达人发"样品已寄出"。实际流程如下。〔10-25 · 代码〕

```
微信（就在这台 Mac 上）
  │  mac_hybrid 后端：从本机微信的数据库读消息，用系统的辅助功能操作微信发消息
  ▼
webot 的消息路由（src/router.py）
  │  名单以外的私聊 → 原来的聊天流程
  │  名单里的达人私聊 ↓
  ▼
达人模块（src/influencer/）
  ├ 从消息里提取商品、收件人、电话、地址、小红书主页（规则，不用大模型）
  ├ 查库存：聚水潭适配器（现在只有模拟模式）
  ├ 查达人数据：小红书 CLI 适配器（CLI 还没交付）
  └ 生成审批单，存进本机数据库
        ▼
控制台「达人审批」页（http://127.0.0.1:7327，默认只能在这台 Mac 上打开）
  └ 运营点"通过" → 复查库存 → 聚水潭建出库单 → 小红书绑定佣金
                → 运营把确认消息复制到微信，发给达人
```

| 部分 | 代码位置 | 现状 | 核实 |
|---|---|---|---|
| 微信收发 | `src/wechat/mac_hybrid_backend.py`（原项目） | 代码已有；这台 Mac 上还没正式收发过消息 | 10-25 · 代码、本机 |
| 达人对话和审批 | `src/influencer/handler.py`、`extract.py` | 可用 | 10-25 · 测试 |
| 数据库 | `src/influencer/store.py` | 可用，4 张表：名单、草稿、审批单、操作记录 | 10-25 · 测试 |
| 聚水潭 | `src/influencer/jst_erp.py` | 只有手动打开的模拟模式，真实接口未接 | 10-25 · 测试、代码 |
| 小红书 CLI | `src/influencer/xhs_cli.py` | 按约定草案写好了调用方式，CLI 未交付 | 10-25 · 测试 |
| 控制台页面 | `ui/src/components/InfluencerPanel.jsx`、`src/influencer/console.py` | 可用 | 10-25 · 浏览器测试 |
| 今日概览（原来的晨报） | 控制台「审批单」页顶部；`src/influencer/store.py` 的 `overview`、`scheduled_agent.py` 的 `morning_brief` | 可用：数字全部来自数据库，点数字进入对应列表，可复制概览文字。定时推送按 D14 不做；物流跟进要等聚水潭真实接口 | 10-25 · 测试 |

## 五、路线护栏：对照 Claude Duet（新增）

原稿以《Build Your Own Duet: The 8-Layer Architecture…》为指导理论，但**这篇文章查不到出处**，不作为依据。〔10-24 · 检索〕现在的参照是：

- Anthropic 2026-10-21 发布的 Claude Duet 研究预览版，官方公告：https://claude.com/resources/articles/claude-duet 〔10-24 · 检索〕
- Shoopy 的使用教程：https://x.com/0xShoopy/status/2113262783605174729 〔10-24 · 检索〕

从中提炼出 7 条规则，每次改代码都要对照：

| 规则 | 在这个项目里的意思 | 现在做到了吗 |
|---|---|---|
| R1 读、起草、准备，自己做 | 识别索样、提取信息、查库存、生成审批单都自动做 | 做到了〔10-25 · 测试〕 |
| R2 发消息、花钱，先问人 | 建单、绑佣金、对达人的承诺都要审批 | 做到了：建单、绑佣金要审批；达人模块的回复不做承诺；达人的其他消息转运营人工回复，不交给聊天机器人；批准后的确认消息由运营手动发〔10-25 · 测试〕 |
| R3 有些事批准了也不做 | 写死的硬上限 | 佣金最高 25%、不达标不寄样已做到；每单件数、每日寄样总量的上限还没定〔10-25 · 测试〕 |
| R4 读到的内容只当数据 | 达人消息不能变成系统指令 | 达人模块现在没用大模型，消息只被规则提取成字段；以后接大模型时要再落实〔10-25 · 代码〕 |
| R5 每一行都要有来源 | 审批单、晨报里的信息都要能追溯 | 做到了：审批单附达人原话和操作记录；今日概览的数字全部来自数据库，能点进对应列表〔10-25 · 测试〕 |
| R6 一天汇报两次，只为急事打断 | 运营集中审批，急事才提醒 | 审批单有效期 72 小时，能等到集中审批；定时汇报和提醒还没做〔10-25 · 代码〕 |
| R7 纠正要记住，人确认才生效 | 驳回原因每周复盘，系统不自己改规则 | 驳回原因已记录；每周复盘还没做〔10-25 · 测试〕 |
