## 一、一页看懂（2026-10-26 晚）

**整条线**：在聚水潭找抖音、小红书达人 → 运营第一次联系、加微信 → 达人在微信里聊，Claude 起草回复、运营审过再发 → 收件信息和商品齐了生成审批单 → 运营批准后在聚水潭「寄样管理」建寄样单 → 专属佣金由运营在平台上另开。〔10-26 · 拍板 D31、D34〕

**架构**：微信登录在同事的 Windows 电脑上，只负责收发；Mac 上的服务处理消息，Claude 在受限的沙箱里起草回复，运营在 Mac 的控制台审核后，经 Windows 发出去。Mac 不登录微信。〔10-26 · 代码；Windows 端 · 告知〕

**已经能用**

- 找达人：另一个 Claude（单独的工作目录 `~/daren-scout`）用我们做的聚水潭命令行搜达人，按你定的标准列候选名单，运营确认后加进聚水潭达人库。第一轮加了 8 位抖音达人，全部读回确认成功。〔10-26 · 本机，真实账号〕
- 聚水潭命令行（`~/jushuitan-engineering`）：找达人、查达人、加达人、查商品和库存、查我们店的合作数据，都在真实账号上跑过。聚水潭没给开放接口密钥，所以照网页的请求自己做的。〔10-26 · 本机〕
- 达人名单里填上抖音号或小红书号，系统自动去聚水潭查**档位**（3 款 / 问专场 / 不限 / 无销售数据）和**主播类型**（直播 / 视频，看哪边卖得多），写给起草的 Claude 看，也显示在名单和审批卡上。〔10-26 · 测试 `test_influencer_tiers.py`〕
- 起草：用同事做的达人副驾驶（PRM）。Claude 只能读业务资料（合作政策、话术）和这位达人的案卷，不能执行命令、上网、调别的工具；每条草稿都由运营审，某类回复运营一直原样通过才会改成自动发，钱和投诉永远人审。〔10-26 · 代码、本机真跑过起草〕
- 审批：合作单进「待寄出」时生成审批单，卡片上有平台、档位、主播类型、商品清单（可以多款）、专场日期、收件信息。批准后建寄样单，给达人的通知也要审过再发。同一张单只能执行一次，重启以后也一样。〔10-26 · 测试 `test_influencer_sample_bridge.py`、`test_influencer_approval.py`，浏览器测试 `test_influencer_console.py`〕
- 涨佣：一开始一律 20%。达人要求涨时，系统不做任何操作，只把他在我们店近 30 天的合作数据和"是否满 40 单或成交额满 1 万"告诉运营，由运营决定。〔10-26 · 拍板 D37；测试 `test_influencer_coop.py`〕
- 全部自动化测试 1741 个通过、2 个跳过、0 个失败。〔10-26 · 测试〕

**还不能用**

## 二、Claude 在系统里做什么、不做什么（替换原稿第一节）

**分工**：系统里有两个 Claude，都碰不到花钱或撤不回的动作。〔10-26 · 代码〕

- **起草的 Claude**：读业务资料和案卷，写回复草稿、建议合作单进哪个阶段。草稿由运营审了才发。
- **找达人的 Claude**：只能用聚水潭命令行的查询和"加达人"，不能发消息、建寄样单、开佣金。第一次联系达人由运营做。

建寄样单、开专属佣金、发消息，都只在运营批准以后由代码执行。

| 保证 | 怎么做到的 | 核实 |
|---|---|---|
| 起草的 Claude 不能执行命令、上网 | 同事 worker 的沙箱：只有读写文件的工具，只能读业务资料目录、只能写案卷，没有外部工具 | 10-26 · 代码、本机 |
| 起草的 Claude 看不到真实的电话和地址 | 案卷里的号码是打码的，审批单生成时才换回真的 | 10-26 · 测试 |
| 回复不经人审就发不出去 | 每类回复一开始都要人审；近 20 条里 18 条原样通过才改成自动；钱、投诉永远人审 | 10-26 · 代码（同事的 PRM） |
| 达人在消息里写"忽略之前的规则"之类的话不管用 | 达人的话只当聊天内容；就算 Claude 被带偏，草稿也要人审 | 10-26 · 代码；模型实际抗干扰的效果未验证 |
| 佣金不会超过 25% | 写死在代码里，运营只能往低改 | 10-26 · 测试 |
| 一张审批单只执行一次 | 数据库里用条件更新占单，两个人同时点也只有一次 | 10-25 · 测试 |

## 三、系统现在是怎么搭的（替换原稿第四节的代码蓝图）

```
找达人的 Claude（~/daren-scout）
  │  聚水潭命令行：搜达人 → 候选名单 → 运营确认 → 加进聚水潭达人库
  ▼
运营第一次联系（加微信 / 一键邀约），把达人加进控制台名单，填抖音号 / 小红书号
  │  系统按号码去聚水潭查档位、主播类型 → 写成达人资料
  ▼
微信（同事的 Windows 电脑，只收发）
  ▼
Mac：达人副驾驶（同事的 PRM）
  │  起草的 Claude（沙箱）读业务资料、案卷、达人资料 → 草稿
  │  运营在「待审批」审 → 经 Windows 发出
  │  收件信息、商品齐了 → 合作单进「待寄出」
  ▼
达人模块（src/influencer/）：生成审批单（平台、档位、商品清单、专场、收件信息）
  ▼
控制台「达人审批」页（http://127.0.0.1:7327，只能在本机打开）
  └ 运营点"通过" → 聚水潭「寄样管理」建寄样单（现在是模拟）
                → 给达人的通知进「待审批」，审过再发
                → 专属佣金：运营在「待审批」用平台动作另开（小红书定向计划、抖音指定达人佣金）
```

## 五、路线护栏：对照 Claude Duet（新增）

原稿以《Build Your Own Duet: The 8-Layer Architecture…》为指导理论，但**这篇文章查不到出处**，不作为依据。〔10-24 · 检索〕现在的参照是：

- Anthropic 2026-10-21 发布的 Claude Duet 研究预览版，官方公告：https://claude.com/resources/articles/claude-duet 〔10-24 · 检索〕
- Shoopy 的使用教程：https://x.com/0xShoopy/status/2113262783605174729 〔10-24 · 检索〕

从中提炼出 7 条规则，每次改代码都要对照：

| 规则 | 在这个项目里的意思 | 现在做到了吗 |
|---|---|---|
| R1 读、起草、准备，自己做 | 找达人、查档位、起草回复、生成审批单都自动做 | 做到了〔10-26 · 测试〕 |
| R2 发消息、花钱，先问人 | 建寄样单、开佣金、对达人的承诺都要审批 | 做到了：每条回复和通知都过「待审批」，建单要运营批准〔10-26 · 测试〕 |
| R3 有些事批准了也不做 | 写死的硬上限 | 佣金最高 25%；寄样上限的机制有，现在不限（你定的按档位寄、不设件数上限）〔10-26 · 测试、拍板〕 |
| R4 读到的内容只当数据 | 达人消息不能变成系统指令 | 起草的 Claude 在沙箱里，没有执行命令的能力；草稿都要人审〔10-26 · 代码〕 |
| R5 每一行都要有来源 | 审批单上的信息都要能追溯 | 审批单附合作单上确认过的信息和操作记录；档位标出销售额区间和查询日期〔10-26 · 测试〕 |
| R6 一天汇报两次，只为急事打断 | 运营集中审批，急事才提醒 | 审批单有效期 72 小时；提醒只做在控制台里，没有推送〔10-26 · 代码〕 |
| R7 纠正要记住，人确认才生效 | 系统不自己改规则 | 驳回原因、运营改过的草稿都有记录；达人专属价、签收后几天发视频这些先不定规则，由运营人工审，以后从运营的决定里总结〔10-26 · 拍板 D38〕 |
