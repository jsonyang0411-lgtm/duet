## 一、一页看懂（2026-10-25 下午）

**新的架构（10-25 定）**：微信登录在同事的 Windows 电脑上，收到的消息转发给 Mac；Mac 上的服务处理消息、由 Claude 生成回复，再把回复交回 Windows 发出去。Mac 不用登录微信。〔10-25 · 拍板；Windows 端转发已做好 · 告知〕

**已经能用（在模拟模式下）**

- 名单里的达人发来的消息可以交给 Claude 回复：每条消息调用一次 `claude -p`，带上最近 20 轮对话和业务资料。Claude 只能用我们给的 4 个工具：查库存、提交寄样申请、查申请和物流状态、转人工；Claude Code 自带的读文件、执行命令等工具全部关掉。这个功能要手动打开（`INFLUENCER_BRAIN=claude`）。〔10-25 · 测试 `test_influencer_claude.py`、`test_influencer_mcp.py`；本机用真实 `claude -p` 跑通，每条 6–8 秒〕
- Claude 的回复发出去之前，代码会检查一遍：承诺发货时间、快递公司、审核结果，提到佣金数字或加佣金，暴露自己是 AI，或者太长，都不发，转给运营。Claude 出错、超时、来回超过 6 轮时，退回原来的规则流程。〔10-25 · 测试 `test_influencer_claude.py`〕
- 达人要求提高佣金时，由代码回复固定话术，不交给 Claude。佣金上限 25% 写死在代码里，同时提醒运营。〔10-25 · 测试 `test_influencer_commission.py`；话术和上限 · 拍板〕
- 运营在控制台「达人审批」页通过或驳回。通过后：复查库存 → 聚水潭建出库单 → 小红书开定向计划（专属佣金）。不发推广链接，达人在小红书选品里自己就能看到这款商品（D17）。同一张单只能执行一次，重启以后也一样。〔10-25 · 测试 `test_influencer_approval.py`，浏览器测试 `test_influencer_console.py`；不发链接 10-26 · 拍板〕
- 执行到一半断电或被强制退出、一直停在"执行中"的单，运营核对后可以在审批卡上标成已执行或失败。〔10-25 · 测试 `test_influencer_interrupted.py`〕
- 寄样上限、防封的发送规则：机制都做好了，具体数字还没定，先用默认值（见第六节、第九节）。〔10-25 · 测试 `test_influencer_sample_limits.py`、`test_influencer_send_policy.py`〕
- 日志里不再出现完整的电话、地址和收件人姓名。〔10-25 · 测试 `test_pii.py`〕
- 全部自动化测试 3568 个通过、1 个跳过、0 个失败，其中达人模块 217 个。〔10-25 · 测试〕

**还不能用**

- Mac 端接收 Windows 转发的服务：还没做，要先拿到同事那边的消息格式。〔10-25 · 代码〕
- 聚水潭：真实接口还没接，库存和单号都是假的。〔10-25 · 代码〕
- 小红书 CLI：同事 10-26 已交付（千帆商家后台的命令行工具），适配器已按它的实际命令改好；还没对真实千帆跑过，要在运行 webot 的电脑上开调试 Chrome 并登录千帆。〔10-26 · 代码、测试 `test_influencer_clients.py`〕
- 物流轨迹：只能告诉达人运单号，还查不到快递到哪了。〔10-25 · 代码〕
- 业务资料（品牌、产品、寄样规则）还没给，Claude 现在遇到产品细节一律转人工。〔10-25 · 代码〕

**现在要注意的**

- 批准后发给达人的确认消息，还是要运营从审批卡上复制到微信里发。自动发送要等 Mac 端接收服务做好。〔10-24 · 拍板 D9；10-25 · 代码〕

## 二、Claude 在系统里做什么、不做什么（替换原稿第一节）

**分工**：Claude 负责"听懂、回话"；查库存、建审批单这些动作通过我们写的工具来做；建单、绑佣金这些花钱或者撤不回的动作，只在运营批准以后由代码执行，Claude 碰不到。常驻运行的是 Python 服务，基础是开源的微信机器人 webot，达人模块挂在它的私聊入口上。〔10-25 · 代码、测试〕

具体的保证：

| 保证 | 怎么做到的 | 核实 |
|---|---|---|
| Claude 不能在电脑上执行命令、读文件 | `claude -p` 用 `--tools ""` 关掉所有自带工具，`--strict-mcp-config` 只挂我们的工具 | 10-25 · 测试 |
| Claude 只能碰正在聊的这位达人 | 每位达人单独起一个工具进程，达人身份由启动参数固定，工具参数里没有"换一个达人" | 10-25 · 测试 |
| Claude 不能建单、绑佣金、改佣金 | 工具里根本没有这些功能 | 10-25 · 测试 |
| 达人在消息里写"忽略之前的规则"之类的话不管用 | 达人的话放在标记里，只当聊天内容；就算 Claude 被带偏，回复也要先过代码检查 | 10-25 · 测试；模型实际抗干扰的效果未验证 |
| 不读到项目里写代码用的规矩 | `claude -p` 在系统临时目录里运行，读不到项目的 CLAUDE.md | 10-25 · 测试 |

原稿第一节有两处要更正：

- "Claude Code 调外部命令必须有人手动确认，非交互下直接报错"：`claude -p` 加 `--allowedTools` 可以只放行指定的工具，不需要人确认，10-25 已在本机跑通。〔10-25 · 本机〕
- "常驻服务（如 fastapi + anthropic SDK）"：实际用的是 webot 自带的、基于 Python 标准库的 HTTP 服务，不是 fastapi。webot 原来的群聊功能用的大模型是 DeepSeek（`AI_BACKEND=deepseek`）；达人的消息打开开关后由 Claude 回复，没打开时用规则流程。〔10-25 · 本机、代码〕

**向上汇报的话术（更正版）**

| 原稿说法 | 事实 | 核实 |
|---|---|---|
| "使用的是 Claude 最顶尖的底层推理大脑" | 达人的消息可以交给 Claude 回复（要手动打开）；群聊等原有功能用 DeepSeek | 10-25 · 代码、本机 |
| "根据生产级工程标准做了服务端容器化" | 没有容器，直接从源码运行；仓库里没有任何容器配置 | 10-25 · 代码 |
| "确保了 7x24 小时无人值守的稳定性" | 还没有长时间运行过 | 未验证 |

建议改成：

> "微信在 Windows 上收发，消息转给 Mac 上的服务处理。回复由 Claude 生成，但 Claude 只能查库存、提交寄样申请、查进度，不能执行命令，也碰不到建单和佣金；回复发出前，代码还会检查有没有乱承诺。建单、绑佣金都要运营在控制台审批后才执行，每张单只能执行一次，佣金上限写死在代码里。目前有 3568 个自动化测试，在模拟模式下全部通过；聚水潭、小红书 CLI 和真实微信还没有联调。"

## 三、系统现在是怎么搭的（替换原稿第四节的代码蓝图）

```
微信（同事的 Windows 电脑）
  │  Windows 端：收消息、转发给 Mac，再把 Mac 的回复发出去（同事已完成）
  ▼
Mac 端接收服务（还没做，要同事的消息格式）
  ▼
webot 的消息路由（src/router.py）
  │  名单以外的私聊 → 原来的聊天流程
  │  名单里的达人私聊 ↓
  ▼
达人模块（src/influencer/）
  ├ 要求提高佣金 → 代码回固定话术，提醒运营
  ├ 其他消息 → Claude（claude -p）
  │     ├ 只能用 4 个工具：查库存 / 提交寄样申请 / 查申请和物流状态 / 转人工
  │     ├ 回复先过代码检查，有问题不发、转人工
  │     └ 出错、超时 → 退回规则流程
  └ 提交寄样申请 → 生成审批单，存进本机数据库
        ▼
控制台「达人审批」页（http://127.0.0.1:7327，默认只能在本机打开）
  └ 运营点"通过" → 复查库存、检查寄样上限 → 聚水潭建出库单 → 小红书开定向计划（专属佣金）
                → 确认消息（现在由运营复制到微信发；以后进发送队列，经 Windows 发出）
```

| 部分 | 代码位置 | 现状 | 核实 |
|---|---|---|---|
| 微信收发 | Windows 端（同事） | 同事已做好转发 | 10-25 · 告知 |
| Mac 端接收 | — | 还没做 | 10-25 · 代码 |
| Claude 回复 | `src/influencer/claude_brain.py` | 可用（要手动打开） | 10-25 · 测试、本机 |
