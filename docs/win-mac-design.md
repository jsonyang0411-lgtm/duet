# Windows 收发、Mac 处理：设计说明（草案）

> 状态：草案，等和同事确认后再动代码。

## 一句话

**Windows 只收发微信，Mac 做所有处理。** 回复达人先由运营在 Mac 的控制台审核，审核通过的话交给 Windows 发出去；以后某类回复运营一直原样通过，就改成自动发（钱、投诉永远要人审）。

```
达人发微信
   ▼
Windows（同事的 webot，"只收发"模式）
   │  收到名单里达人的私聊 → 原样转给 Mac（文字；图片、语音先在 Windows 解好）
   │  运营在 Windows 微信上自己回了达人 → 也转给 Mac（Mac 据此知道运营接手了）
   ▼
Mac（我们的 webot）
   ├ 谈佣金：代码回固定话术
   ├ 其他：Claude 起草回复（只能查库存、提交寄样申请、查进度、转人工）
   ├ 回复草稿进控制台「待审核」：运营点 发送 / 改了再发 / 不发
   │     某类草稿最近 20 条有 18 条原样发出 → 这类以后自动发（钱、投诉除外）
   ├ 索样信息齐了：查库存、查粉丝、检查寄样上限 → 审批单 → 运营批准
   │     → 聚水潭建出库单 → 小红书开定向计划（专属佣金）
   └ 要发给达人的话（审核通过的回复、批准后的确认消息）按防封节奏排队
   ▼
Windows 按 Mac 的指令发出，发完回读确认，把结果告诉 Mac
```

## 两台机器各做什么

| | Windows | Mac |
|---|---|---|
| 微信 | 登录、读消息、发消息、解图片、语音转文字 | 不登录 |
| 达人名单 | 只用来决定读哪些私聊，名单从 Mac 同步过来 | 维护名单（控制台） |
| 回复 | 只按指令发 | Claude 起草、运营审核、逐步自动 |
| 寄样 | — | 审批单、聚水潭、小红书 CLI（调试 Chrome 登录千帆） |
| 控制台 | 同事原有的页面照旧（中转、微信连接等） | 达人审核、审批单、待处理、名单 |
| 数据 | 消息原文按保留期清除 | 草稿、审批单、对话按保留期清除 |

## 中间传什么

复用同事的中转连接：Windows 开服务（默认端口 8790），Mac 来取，请求带口令（`Authorization: Bearer`），只走局域网，断线自动重连。在它上面加三样东西：

| 方向 | 内容 | 说明 |
|---|---|---|
| Windows → Mac | **达人消息**：chat_id、昵称、消息原文、类型、时间、附件 | 新的任务类型，比如 `creator_msg`。Mac 用已有的取任务接口拿 |
| Windows → Mac | **运营自己发的消息**：chat_id、原文、时间 | 同上，类型比如 `own_msg`。用于"运营接手"和给 Claude 补上下文 |
| Mac → Windows | **请发这句话**：chat_id、文字、文件、一个不重复的编号 | 新接口，比如 `POST /relay/send`。同一个编号只发一次 |
| Windows → Mac | **发送结果**：发出 / 回读确认 / 失败 | 比如 `GET /relay/send/<编号>` |
| Mac → Windows | **达人名单**：chat_id 列表 | 比如 `PUT /relay/creators`。Windows 只读这些私聊 |

## 两边的代码怎么用

- **同事的代码**：Windows 端的中转、解图、语音、发送回读确认、识别"运营自己发的消息"照用。PRM 里的草稿状态、自动放行、接管、清除这些逻辑，搬到 Mac 端用（同一份 webot 代码，Mac 上也能跑）。
- **我们的代码**：达人模块（审批单、聚水潭、小红书、各种上限）不变。`claude_brain.py` 从"直接回复"改成"起草"，草稿进审核；防封节奏（`send_policy.py`）放在 Mac 发指令之前。
- **Windows 那台跑的版本**：我们仓库合并了同事分支之后的版本，打成 EXE 交给同事装。

## 先不做的

- 全部搬到 Mac（不用 Windows）：这台 Mac 读不了微信数据库（密钥拿不到，B26），Mac 上发消息还会抢键盘焦点，暂不考虑。
