达人寄样流程现状

从达人发来消息到发货、跟进的每一步，以及每一步做到了什么程度。依据：merge-edge 分支的代码（已推到 duet）、handoff.md v36，2026-10-26。

● 已实现（有测试） ● 部分实现 / 只有模拟 ● 未实现 ● 等外部（同事、账号、真机）
能跑通的

用同事的"假 Windows"测试：达人发消息 → Claude 起草 → 运营审核 → 经 Windows 发出、读回确认；收件信息齐了 → 审批单 → 批准 → 建单、绑佣金（模拟）→ 通知进待审批。起草的沙箱在这台 Mac 上用真实 Claude 跑过两次。

等外部的

和同事的 Windows 真机联调（第 7 步）；聚水潭真实接口（要账号）；小红书 CLI 在真实千帆上跑（要登录）；业务资料（寄样规则、商品、话术，还没定）。

还没做的

自动查物流、签收后跟进发布；Mac 这边的"夜里不主动发"等防封节奏还没接到新发送路径上；真实聚水潭的运单号回填；联调通过后删旧代码（第 8 步）。

Windows（同事的 webot，只收发）
  • 登录微信，只读名单里达人的私聊
  • 解图片、语音转文字、取文件
  • 按 Mac 的指令发消息，同一条只发一次
  • 读回确认；认出运营亲手回复
  • 名单以外的私聊不回（D24）
达人消息 → ← 名单 ← 请发这句 发出 / 读回 → 局域网 + 口令
Mac（我们，处理一切）
  • 不登录微信
  • Claude 在沙箱里起草，运营在控制台审核
  • 审批单、聚水潭建单、小红书开佣金
  • 名单、合作单、个人信息 90 天清理
  • Windows 出问题时控制台顶上提醒
1

达人发微信，Windows 转给 Mac 同事的 Windows 边缘 + 我们的 edge 后端

Windows 读名单里的私聊、转成事件同事已完成

同事 wechat-edge 分支（PRM_EDGE=on）。图片、文件在 Windows 取好，Mac 下载后再交给 Claude。

Mac 拉事件、推名单已实现

WECHAT_BACKEND=edge：Mac 不登录微信，去 Windows 拉消息；连不上就退避重试；重启后从上次读到的地方接着读，不重复处理。

Windows 真机等联调

同事 10-26 用旧版 EXE 在真机上测过收消息、起草、发出：读回不到 1 秒；测出"长文字被当成图片、误判运营接管"的问题，已修好并合进来。新的只收发模式还没在真机上跑过。

2

是不是名单里的达人

一份名单已实现

以「达人审批 → 达人名单」为准，合作单页登记或停用的也同步回来。名单变了 Mac 就推给 Windows，Windows 只转名单里的人。

名单以外的私聊不回

D24：Windows 不转、不自动回复，由人工处理。

3

Claude 起草回复 同事的起草沙箱，在这台 Mac 上

号码先换成占位符已实现

手机号、证件号变成〈手机1〉这种占位符才交给 Claude，发出前再换回来。

沙箱起草本机跑过

同事的 worker（--kinds prm）：只能读业务资料、只能改这位达人的案卷，不能运行命令、不能上网；结果按固定格式交回（回复、类型、已确认信息、建议阶段）。代理已写进 ~/.claude/settings.json，双击启动也能用。

业务资料（kb/）等规则

寄样规则、可寄的商品、常见问答还没定，现在用的是同事的样例。资料里没有的，Claude 会写"我确认一下再回复"并提醒运营。

分支：达人要求提高佣金 ↓

固定话术，等人审已实现

D22：佣金上限 25%。用户给的固定话术作为"系统消息"放进待审批，一定人审；同一位达人 6 小时内只放一条，同时记进「待处理」。

4

运营审核 控制台「待审批」页

发送 / 改了再发 / 不发已实现

D19：先人审。号码默认打码显示，看完整号码要点一下并留记录。

逐步自动已实现

某一类回复最近 20 条有 18 条原样发出、关键信息没改过，这一类以后自动发；钱和投诉永远人审；标"发错了"立刻退回人审。

没人处理先回"稍等"已实现

草稿放了 10 分钟没人处理，先回达人一句"收到，我确认一下马上回你"，每轮消息最多一次。

运营亲手回复 → 人工接管已实现

运营在微信里自己回了，Windows 认出来告诉 Mac：这位达人转人工 2 小时，等着的草稿作废；结束后下一份草稿会带上双方说过的话。

5

经 Windows 发出 Mac 下指令，Windows 发

只发一次、读回确认已实现

每条有编号，重复提交也只发一次。Windows 读回后草稿标"已确认"；没发出去（失败、过期、不确定）的草稿改成"没发出去"并写原因。

防封节奏只有 Windows 那层

Windows 管账号级节奏（两条至少隔 3 秒、每小时最多 60 条）。Mac 这边原来的"像真人打字的等待、夜里不主动发"（send_policy.py）还没接到新的发送路径上；参数也还没定。

6

收件信息齐了 → 生成审批单 合作单进「待寄出」时

从合作单生成审批单已实现

D26：Claude 建议进「待寄出」，或运营在合作单页改成「待寄出」时，用合作单上确认过的商品、收件人、手机、地址生成审批单。缺哪项就在合作单上提示；每位达人同时只有一张在等的单。

查库存（聚水潭）只有模拟

没库存就不生成，在合作单上提示，并记进「待处理」。真实接口要聚水潭账号。

查资质（小红书 CLI）待真机

D16：只看粉丝 ≥ 1 万，只标注不自动拒绝；点赞由运营审批时复查。要在真机上开调试 Chrome 登录千帆。

7

运营审批 → 建单、绑佣金 控制台「达人审批」页，批准后由代码执行

审批页已实现

通过或驳回；可以补填小红书账号、把佣金调低（上限 25%）；每张单只执行一次，批准时重新查库存；执行到一半中断的可以人工核对后标记（B23）。

聚水潭建出库单只有模拟

真实聚水潭建单时大概率还没有运单号，要仓库打单后才有，到时要回填。

小红书开专属佣金（定向计划）待真机

指定这位达人、这款商品、这个佣金；计划名用审批单号，不会开两次。不发推广链接，达人在选品里自己能看到（D17）。

8

通知达人 系统消息，进「待审批」

批准 / 驳回的通知等人审已实现

批准通知（带运单号、说明已开专属佣金）和驳回的婉拒话术，都作为系统消息放进待审批，审核后经 Windows 发出。审批卡上不再显示"复制"，免得发两遍。

运单号进合作单已实现

聚水潭给了运单号就直接记进合作单，阶段改成"已寄出"，不用运营再填。

9

发货、物流、签收 「合作单」页

打包、发货仓库 / 聚水潭

不归我们的代码管。

手动填运单、更新物流已实现

运营在合作单页填运单号会生成发货通知草稿（单号由系统填，不让模型写）；可以改成运输中、已签收、物流异常。

自动查物流未实现

要先确认聚水潭能不能返回物流轨迹，不能的话接快递100之类的服务。

10

签收后跟进发布

合作单阶段只能手动

合作单有"素材已发、初稿已交、修改中、已发布、结案"这些阶段，运营手动改；Claude 也会建议阶段。

主动提醒发笔记未实现

还没设计。
