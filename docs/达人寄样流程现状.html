达人寄样流程现状

从达人发来消息到发货、跟进的每一步，以及每一步做到了什么程度。依据：仓库代码 851e2fd、handoff.md v15 和用户 10-25 的补充，2026-10-25。

● 已实现（有测试） ● 部分实现 / 只有模拟 ● 未实现 ● 等外部（账号、同事、真机）
能跑通的

在模拟模式下，从"达人说要样品"到"运营批准、生成运单号和要发给达人的消息"已经全程跑通。状态、审批记录都存进了数据库，每张单只会执行一次。

卡在外部的

聚水潭的真实接口、小红书 CLI、Windows 真机验证。这几项不到位，就只能用假数据跑。

还没做的

Mac 端接收转发、把 claude -p 接进流程、谈佣金的固定回复、推广链接、自动给达人发消息、查物流、发布跟进。

1

收到达人的微信私聊 Windows 登录微信收发消息，Mac 负责处理

Windows 后端读私聊等真机

wcdb_backend.py 能读私聊，但要设 PRIVATE_CHAT_ENABLED=true。PRIVATE_CHATS=* 只读 wxid_ 开头的账号，老式微信号要单独列出来。达人流程还没在真机上跑过。

Windows 端转发消息同事已完成

Windows 把收到的消息发给 Mac，再把 Mac 给出的回复发回微信。

Mac 端接收转发未实现

Mac 上要开一个服务，接收 Windows 发来的消息，交给达人模块和 Claude 处理后，把回复返回给 Windows。要先拿到同事那边的消息格式和鉴权方式。

Mac 本机登录微信不需要

链路打通后，Mac 只处理消息，不登录微信。B25（Mac 后端不读私聊）和 B26（没有数据库密钥）就不用修了。

2

判断是不是达人

达人名单（白名单）已实现

名单存在数据库里，在控制台「达人名单」页添加或停用。按 chat_id 判断，不看昵称（B10、B11）。

不是达人 → 普通聊天已实现

D13：名单以外的私聊照常交给原来的聊天模型回复（这是公司号）。

3

理解达人想干什么 现在用规则，接下来改用 Claude

规则识别已实现

extract.py 用关键词和正则识别要样品的意图，提取商品、姓名、电话、地址和小红书账号。

用 Claude 理解、回复消息已跑通，未接入

10-25 在本机调用 claude -p 已经能回复消息，还没接进流程。接入时只开放我们自己做的工具，Claude Code 自带的工具全部关掉。

分支：不是要样品的消息（闲聊、问发货、谈佣金）↓

转人工 + 回一句中性的话已实现

B20：消息记进控制台「待处理」，机器人回"我们核对一下再回复"，同一位达人 6 小时内最多回一次。

闲聊由 Claude 回复未实现

避免一直用固定话术，回复范围受知识库限制。业务资料（品牌、产品、寄样规则）还需要你提供。

谈佣金：代码固定回复话术已定，待开发

佣金上限 25%。达人要求提高时由代码回复固定的话，不交给 Claude 判断，同时记进「待处理」。话术开头是"特别理解老师的想法！坦白讲我也特别希望能给老师申请更高点位……"，结尾建议先收样品再对排期。

4

补齐申请信息（多轮对话）

申请草稿已实现

缺什么就问什么：先问要哪款商品，再问收件人、电话、地址，最后问小红书主页。草稿存在数据库里，重启不会丢；放太久没动静的会作废。

后补小红书账号已实现

审批单已经提交后达人才发来主页的，会自动补到那张待审批单上。

5

查库存 聚水潭

查库存的流程已实现

换了商品就重新查；查询出错时转人工，不会乱回复。

聚水潭真实接口等账号

jst_erp.py 目前只能在模拟模式下用；不开模拟时直接报错，不会假装成功（B6）。第 5 阶段要拿到真实账号再接。

缺货 → 告诉达人 + 通知运营已实现

B21：告诉达人暂时没货、可以换别的产品，同时在控制台「待处理」里提醒运营。

6

查达人资质 小红书 CLI

资质只标注、不自动拒绝已实现

D4、D12：门槛是粉丝 ≥ 1 万且最近点赞 ≥ 1000，只在审批单上标出来，由运营决定。拿不到数据就写"未知"，不编数字（B8）。

小红书 CLI等同事

适配器按约定的命令格式写好了，CLI 本身由同事开发、还没交付。

7

生成审批单

审批单入库已实现

写明商品、库存、成本、佣金、收件信息、资质和不可撤销的后果。72 小时有效（D8）。回复达人"已提交审核"，不承诺发货时间（B1）。

8

运营审批 控制台「达人审批」页

审批页已实现

可以通过或驳回，可以补填、更正小红书账号和佣金（上限 25%，写死在代码里）。左栏角标显示有几件事等着处理，还有「今日概览」。

保证只执行一次已实现

用条件更新防止重复执行；批准时重新查一次库存；驳回或过期的单不能再执行（B2、B22）。

驳回 → 婉拒话术已实现

生成礼貌的婉拒消息，由运营复制后手动发送（按方案，驳回一直走手动）。

9

执行：建单 → 绑佣金 批准后由代码执行，不交给 Claude

聚水潭建出库单只有模拟

执行顺序和失败处理都做好了，模拟模式会返回一个假的单号和运单号。要核实：真实的聚水潭建单时大概率还没有运单号，要等仓库打单后才有。

小红书绑专属佣金只有模拟

建单成功后才绑佣金（B3），审批单号作为防重复的标识传过去。等 CLI 交付。

生成商品推广链接未实现

链接由小红书平台生成，要通过小红书 CLI 调用。我们后台负责：调用 CLI、把链接存进审批单、在审批卡上显示、写进发给达人的消息。后台这部分可以先用模拟数据做。

执行失败 → 标记为失败已实现

保留已经建好的单号，提示运营去人工核对。

执行到一半中断已实现

B23：开始执行 10 分钟后还停在"执行中"的单，运营到聚水潭和小红书核对后，在审批卡上标成已执行（填出库单号）或失败（写核对结果）。

10

通知达人"已安排发货"

生成要发的消息已实现

审批卡上显示消息原文：批准前是预览，执行后带上运单号。目前由运营复制后手动发送（D9）。

自动发送未实现

B15，方案已经定了：机器人在运行就自动发，没在运行就退回手动复制。

11

仓库打包发货 → 达人问物流

打包、发货仓库 / 聚水潭

不归我们的代码管，由仓库在聚水潭里完成。

查物流工具未实现

达人问"到哪了"时由 Claude 调用这个工具来回答。要先确认聚水潭能不能返回物流轨迹，不能的话就接快递100之类的服务。

主动跟进物流未实现

B13 的物流跟进部分：定时任务从来没启动过，等聚水潭接入后再做。

签收后跟进发布

提醒达人发笔记、记录发布情况未实现
